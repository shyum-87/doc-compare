# rag_ko.md 형식

이 시스템의 입력 문서 형식이다([DECISIONS.md](DECISIONS.md) D-006).

원본 SOP(Word/PDF/Excel/PPT)를 LLM이 Markdown으로 재구성하고 한국어로 번역한 단일 텍스트 파일이다. 사람이 쓴 Markdown이 아니라 자동 변환 산출물이다.

생성 경로: 원본 → 파서 JSON([PARSER_OUTPUT.md](PARSER_OUTPUT.md)) → `rag.md`(LLM 재구성) → `rag_ko.md`(한국어 번역).

## 구성 요소

| 요소 | 형태 | 규칙 |
|---|---|---|
| 페이지 마커 | `[PAGE N]` | 원본 페이지 경계. 해당 페이지 내용 **앞**에 오는 여는 마커이며 닫는 마커는 없다. `[PAGE 9]`부터 `[PAGE 10]` 직전까지가 9페이지다. 근거 위치를 추적할 수 있는 유일한 장치다. 중간 번호가 빠질 수 있으므로 순번으로 세지 말고 문자열 안의 숫자를 읽는다. |
| 헤딩 | `##`, `###` | 원본 제목 계층을 반영한다. `3.1`, `3.2` 같은 조항 번호는 번역되지 않고 유지되므로 절 식별자로 쓴다. |
| 표 | Markdown 표 | 행·열의 수와 순서가 보존된다. 셀 안 줄바꿈은 `<br>`이다. 병합 셀은 값이 반복되거나 하위 표로 분리된다. 핵심 수치와 필수 입력값이 표에 있는 경우가 많으므로 본문만 읽으면 안 된다. |
| 이미지 | `![img021](<img021.png "제목">)` | 괄호 안 제목은 그림을 판독한 결과가 **아니다**. Word/Excel은 이미지를 모델에 보내지 않으므로 주변 텍스트에서 추론한 제목이다. 그림 안에만 있는 정보는 이 파일에 없다. |
| 원문 유지 항목 | 숫자, 단위, 설비 ID, Part Number, 코드(`WI-BK-204`), 파일 경로 | 번역되지 않는다. 기술 용어는 `발효(fermentation)`처럼 병기될 수 있다. |

## 한계

자동 변환이라 문장이 어색하거나 끊긴 구간이 있고, 표 구조가 완벽히 복원되지 않을 수 있다. 이 파일을 읽는 모든 단계(어댑터, LLM 프롬프트)는 **추측해서 보완하지 않는다.** 읽을 수 없거나 모호한 부분은 그대로 표시하고 사람 검토로 넘긴다.

## 샘플

[tests/fixtures/rag_ko/sample_bakery_sop.md](../tests/fixtures/rag_ko/sample_bakery_sop.md)는 가상의 제빵 SOP 8~11페이지다. 변환 산출물의 특징을 그대로 담은 테스트 기준이므로 오탈자나 표기를 고치지 않는다.

샘플에서 보이는 표기 특징은 다음과 같다. 어댑터가 모두 처리해야 한다.

- **이미지 문법이 표준 Markdown과 다르다.** 꺾쇠 안에 파일명과 제목이 함께 들어 있어 일반 Markdown 파서는 제목을 분리하지 못한다.
- **목록 표기가 섞여 있다.** `1)`, `- `, 공백 없는 `-`가 모두 나온다.
- **강조 뒤에 공백이 없을 수 있다.** 예: `**주의:**LotNo.가`.
- **표 행 끝에 공백이나 빈 셀이 붙을 수 있다.** 예: `| |`, 행 끝의 `| `.
- **절과 페이지는 서로 독립이다.** 한 페이지에 여러 절이 있고(11페이지의 3.4, 3.5), 상위 절은 여러 페이지에 걸친다(8페이지에서 시작한 3절).
- **오탈자와 띄어쓰기 오류가 있다.** 예: `합께`, `패덜`, `현항`.

## 설계에 주는 의미

- 근거 위치는 페이지 번호 + 조항 번호로 만들고, 표는 표 순번 + 행 + 열을 더한다.
- 숫자·단위·코드는 원문 그대로이므로 코드로 결정적으로 검사할 수 있다.
- 이미지는 읽지 못한 영역이다. 이미지가 있는 구간에서는 "근거 없음"을 확정할 수 없다.
- 파서 JSON에 있던 실패 신호(표 fallback, `null` 셀)가 이 파일에는 없다. 변환·번역 단계의 오독과 누락은 이 파일만으로는 드러나지 않는다.
